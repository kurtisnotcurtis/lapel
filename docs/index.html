Four pillars

Running local coding agents on Windows means bridging four gaps that break out of the box. lapel solves all four in one control plane.

1 Cross-boundary reachability

Resolves the real Windows host gateway IP from /proc/net/route inside WSL2 and classifies connection-refused vs. timeout vs. bind-address errors from the Linux side.

2Lean WSL2 (Ubuntu-Lean)

A minimal distro with only what coding agents need (git, curl, tmux, ripgrep, sshd). No GUI apps, no desktop bloat, and PATH filtered to prevent /mnt/c leakage.

3 Sandboxing & honest reporting

Filesystem scoping, process timeouts, and non-root execution (agent user). Distinguishes controls that are actively enforced, requested, or unsupported.

4 Hardware-aware config sync

Detects GPU VRAM and system RAM to recommend model tiers, context windows, and batch sizes, syncing configs to your CLI agents and IDE extensions.

The user journey

Start interactively with three commands, or manage reproducible team environments declaratively via lapel.yaml.

lapel doctor

Verify WSL2 availability, GPU/VRAM specs, model tier recommendations, and provider reachability.

lapel setup

Guided setup to verify providers, provision Ubuntu-Lean, mount your workspace, and configure jail policies.

lapel run

Launch your coding agent (pi, claude-code, copilot) inside the sandboxed WSL environment.

init / plan / apply

Declarative lapel.yaml lifecycle backed by SQLite drift detection (.lapel/state.db).

Supported providers & agents

Bring your own inference server and your own coding agent — lapel wires them together cleanly.

Category Supported Targets How lapel Integrates
Inference Providers LM Studio, Ollama Detects Windows installation & runtime status; lists loaded models; resolves WSL-to-Windows host gateway IP
CLI Coding Agents Pi, Claude Code, GitHub Copilot CLI Auto-detects installed binaries in WSL; injects resolved provider endpoint, active model, and jail environment

Declarative configuration (lapel.yaml)

Scaffold a reproducible project manifest with lapel init and apply it with lapel apply.

apiVersion: lapel.dev/v1
name: my-project

environment:
  distribution: Ubuntu-Lean
  base: ubuntu
  version: "24.04"
  packages:
    - fd-find
    - tree

provider:
  name: local
  type: lm-studio
  baseURL: "http://127.0.0.1:1234"
  connectionTimeout: 8s

agent:
  name: pi
  provider: local

workspace:
  name: my-project
  path: "."
  importMode: bind   # "bind" for live bind mounts or "copy" for isolated rsync copies

jail:
  name: developer
  profile: developer
  user: agent
  filesystem:
    "C:\\Users\\user\\Projects": read-write
    "C:\\Windows\\System32": deny
  network: unrestricted
  processes:
    privileged: false
    timeoutSeconds: 300

Local-first privacy

Hardware detection and baseline model recommendations run 100% locally during lapel doctor and lapel setup. Optional community benchmark sharing (lapel community) is strictly opt-in via LAPEL_COMMUNITY_ENABLED=true, and can be pointed at a self-hosted backend via LAPEL_COMMUNITY_ENDPOINT.
